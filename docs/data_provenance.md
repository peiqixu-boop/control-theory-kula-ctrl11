# Data provenance and processing

- `config/experiment.json`: plant parameters from Example 1 (PDF p.10); numerical choices belong to this implementation.
- `data/reference/table1.csv`: three selected rows manually transcribed from Table 1 (PDF p.16), checked against the rendered page. Order of metrics in the paper is IAE, ITAE, ISE, ITSE.
- `data/reference/figure_features.csv`: approximate settling-time annotations read from Figures 2 and 8. These are not raw sampled trajectories.
- `results/derived_parameters.csv`: calculated from the paper's tuning rules, not copied from printed controller gains.
- `data/generated/*.csv`: synthetic time series generated by the independent model. Columns are time_s, reference, output, error and control. Each baseline contains 100001 samples on [0,100] s at h=0.001 s.
- `src/analysis.py`: reloads all three generated CSV files, verifies their column names, finite entries, increasing time and error identity, then calculates metrics and loads the reference CSV for comparison. Results are in `results/data_checks.json` and `results/comparison_table1.csv`.

No external measured dataset or author-supplied simulation code was used. The simulation data and transcribed paper reference values are kept separate.

CSV values use 17 significant digits to preserve float round-tripping and the error-column identity near steady state. The run log records the completed pipeline.

The baseline uses full-precision controller gains and a fixed 100 s horizon. The 20/30/50/100 s sensitivity to integration horizon is reported separately; the 30 s result is not substituted merely to reduce published discrepancies. Input/configuration and core-code SHA-256 hashes plus package versions are in `results/environment.json`.

## Repository storage

The saved baseline outputs were generated on Windows. The full CSVs are stored losslessly as gzip parts in `data/generated/archive/`; the manifest records the byte length and SHA-256 of each CSV and each part. `analyse_saved_data.py` restores absent CSVs automatically and verifies the manifest. This is storage compression, not downsampling or rounding. `run_replication.py` still writes ordinary CSV files. `tools/pack_data.py` refreshes the archive after a new run.

The separate `results/chr_integral_diagnostic.json` records a focused 30/100/200 s CHR rerun with two step sizes, package versions and input hashes. It does not replace the primary 100 s result files. Its analytic moments are signed-error identities; their interpretation as absolute-error metrics requires the conditions explained in [validation.md](validation.md).
